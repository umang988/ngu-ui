The screen people use

Why ngu-table

One method, a whole screen
fetchFn gets page, size, search, sort and filters in the shape a Spring Data Page answers. The table does the rest, the same way on every screen.
Columns that know their type
Dates, amounts (rupees in lakhs if you like), status badges with colors that mean something, avatars, links and progress bars, from one line of config each.
No stale answers
A new search, sort or filter cancels the request in flight. Rows stay put, dimmed, while the next page loads; skeletons only before the first.
Filters that apply when you say
A filter panel applied with one button, tabs that apply at once, and one Clear that resets search, sort and filters in a single request.
Row actions with rules
View, Edit and Delete with per-row rules, a native confirmation dialog, clickable rows and room for your own buttons.
Accessible
Sort buttons with aria-sort, announced page changes, named icon buttons, keyboard rows, forced colors and reduced motion. The site is checked with axe.
