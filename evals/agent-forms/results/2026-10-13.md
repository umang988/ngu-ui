# 2026-10-13: ngu-form 0.6.0, Claude Code 2.1.296 with Sonnet

Each case ran once per variant: `none` is the package without `docs/` and `skills/` (the agent
still has the README and the type definitions), `agents` adds the notes through
`ng g ngu-form:ai`. Every app built and no run left console errors.

The structural score did not separate the variants: the README teaches the API well enough. The
code did. Selectors reaching into ngu-form's internal classes (`::ng-deep .ngu-…`), which break
when the library changes:

| Case | `none` | `agents` |
| --- | --- | --- |
| checkout | 0 | 0 |
| invoice | 13 | 0 |
| job-application | 18 | 0 |
| settings | 6 | 0 |
| signup | 2 | 0 |
| survey | 87 | 0 |

With the notes, agents set about twice as many theme tokens instead (11 to 14 per form against
4 to 8), and reported the details tokens could not reach rather than overriding them. Without
the notes, agents matched a few of those details more closely (choice options in columns,
uppercase table headers, the drop zone's text) through those overrides. The missing styling
hooks are listed under "Known gaps" in `ROADMAP.md`.

## Changes after round 1

- Rules and guide: a plain `cols: 2` collapses below a 480px form; narrow cards need
  `cols: { base: 2 }`.
- Guide: build every tab or step with ngu-form's `layout` even when only one shows, with
  plausible fields for the hidden ones, listed as guesses.
- Guide: open every screenshot you take; a field list cannot show colors or spacing.
- Guide: class map slots for details that tokens do not reach; never `.ngu-…` or `::ng-deep`.
- Runner: tabs must be ngu-form's own; `sleep`, `echo`, `wc`, `sed` and `cd` allowed so an agent
  can start a server and take a screenshot in one command.
